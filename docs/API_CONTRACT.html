1. Authentication & Authorization

All protected endpoints require a valid Bearer token from Microsoft Entra ID. Include on every request:

Authorization: Bearer <access_token>
Content-Type: application/json

Auth Labels

LabelRequired AccessCode Pattern
AnonymousNo token requiredNo .RequireAuthorization()
AuthenticatedAny valid Entra token.RequireAuthorization()
PropertyWriteValid token + matching {propCode}_wh role or DatabaseManager.RequireAuthorization() + inline property check
DatabaseManagerValid token + DatabaseManager role.RequireAuthorization("DatabaseManager")
CallbackTokenNo Entra token. The vendor cart session's callback_token in the request body. Browser extension calls only. Five failed attempts for a session → 429No .RequireAuthorization(); token checked in the endpoint
FunctionAppValid token + PropertyChannelFailure.Write role — Azure Functions only.RequireAuthorization("FunctionApp")

Role Tiers

TierAccessHow Assigned
DatabaseManagerFull access — all warehouses, all bulk/destructive/administrative operations. Overrides all property checks. Auto-joined to all warehouse SignalR groups.M365 group Inventory-DatabaseManagers → App Role in Azure Portal. No code change required.
{propCode}_whRead all. Write access scoped to matching warehouse only (for example supply creates, single and bulk; adjustments; scan in).App Role per property on ATC_InventoryAPI. See Entra_Property_Access_Management.md.
Baseline AuthenticatedRead all. Creates parts, identifiers, vendor-parts and vendor aliases. Part updates. Scan out (/supplies/scan/consume), PUT /supplies/{supplyId} and equipment scans.Any valid Entra user with a token. No role assignment required.
FunctionAppNotification failure endpoints only.Managed Identity App Role on ATC_InventoryAPI.
Single-create vs bulk: Single creates of parts, identifiers and vendor-parts are open to any authenticated user. PUT /parts/{id} follows the single-create rule. Supply creates, single and bulk, require DatabaseManager or the {propCode}_wh role of every warehouse in the request. Other bulk and destructive operations require DatabaseManager.
The PWA uses role claims for UI show/hide only. The API always enforces independently. A 403 is always possible regardless of frontend state.

6. SignalR Events

Hub URL: /hubs/inventory  ·  Token via query string: ?access_token=<token>

Events are cache invalidation signals only — not authoritative state. The PWA always re-fetches from the API on receipt.

The SignalR connection is additive and non-blocking. The app must function fully if the hub is unavailable. No feature may fail or hang due to a missing connection.

Warehouse Groups

Hub Method (client → server)Effect
JoinWarehouse(int warehouseId)Adds connection to warehouse_{warehouseId} group
LeaveWarehouse(int warehouseId)Removes connection from group

9b. Vendor Cart (web cart fill)

Fills a vendor's web cart through the browser extension. The PWA starts a session (preflight) and hands the session's callback_token to the extension. The extension reports the cart's contents (reconcile) and ends the session (mark-ordered or release). The PWA lists the caller's sessions, asks the owner whether an ended session's orders were ordered (resolve), and adds extra cart lines as orders.

Transition: the API is on the v4 flow below. Until the v4 extension and PWA ship, they still use the pre-v4 sequence: confirm (deprecated) followed by mark-ordered. Because mark-ordered now requires an open session and confirm completes the session, that sequence can no longer mark orders ordered.

Sessions

StatusMeaning
openFrom preflight until the session ends. Holds the cart lock while not expired. Lasts 2 hours; a checkout reconcile resets the 2 hours.
completedOrder submitted (mark-ordered)
abandonedReleased (extension release or PWA abandon-session), or expired. An expired open session is closed by the 15-minute cleanup service, by the next preflight for the same lock, or by resolve.
overriddenForce-released by a DatabaseManager
  • Cart lock: one open session per vendor and lock key. The key is company or the warehouse's property code, from the web_cart cart_scope. Enforced by a unique filtered index; an expired holder does not block a new session.
  • Unresolved sessions: an abandoned or overridden session with orders still cart_filled waits for the owner to answer through resolve. A session that ends through release, abandon-session, the cleanup service or an override with no order in cart_filled is marked resolved at once.
  • Callback token: 64 hex characters (32 random bytes) returned only by preflight; the API stores only its SHA-256 hash. It is sent only in request bodies, never returned by sessions/mine, and cleared when the session ends (except by the deprecated confirm). Failed attempts are counted per session in memory; five return 429.
